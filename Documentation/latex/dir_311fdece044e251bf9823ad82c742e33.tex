!\mbox{[}Node\mbox{]}(\href{https://github.com/creationix/http-parser-js/workflows/Node/badge.svg}{\texttt{https\+://github.\+com/creationix/http-\/parser-\/js/workflows/\+Node/badge.\+svg}}) \hypertarget{README.md_autotoc_md11512}{}\doxysubsection{\texorpdfstring{HTTP Parser}{HTTP Parser}}\label{README.md_autotoc_md11512}
This library parses HTTP protocol for requests and responses. It was created to replace {\ttfamily http\+\_\+parser.\+c} since calling C++ functions from JS is really slow in V8. However, it is now primarily useful in having a more flexible/tolerant HTTP parser when dealing with legacy services that do not meet the strict HTTP parsing rules Node\textquotesingle{}s parser follows.

This is packaged as a standalone npm module. To use in node, monkeypatch HTTPParser.

This should now be usable in any node application, it now supports (nearly) everything {\ttfamily http\+\_\+parser.\+c} does while still being tolerant with corrupted headers, and other kinds of malformed data.\hypertarget{README.md_autotoc_md11515}{}\doxysubsubsubsection{\texorpdfstring{Node versions}{Node versions}}\label{README.md_autotoc_md11515}
{\ttfamily http-\/parser-\/js} should work via monkey-\/patching on Node v6-\/v11, and v13-\/14.

Node v12.\+x renamed the internal http parser, and did not expose it for monkey-\/patching, so to be able to monkey-\/patch on Node v12, you must run {\ttfamily node -\/-\/http-\/parser=legacy file.\+js} to opt in to the old, monkey-\/patchable http\+\_\+parser binding.\hypertarget{README.md_autotoc_md11516}{}\doxysubsubsection{\texorpdfstring{Standalone usage}{Standalone usage}}\label{README.md_autotoc_md11516}
While this module is intended to be used as a replacement for the internal Node.\+js parser, it can be used as a standalone parser.
