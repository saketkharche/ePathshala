DOMPurify is a DOM-\/only, super-\/fast, uber-\/tolerant XSS sanitizer for HTML, Math\+ML and SVG.

It\textquotesingle{}s also very simple to use and get started with. DOMPurify was \href{https://github.com/cure53/DOMPurify/commit/a630922616927373485e0e787ab19e73e3691b2b}{\texttt{started in February 2014}} and, meanwhile, has reached version {\bfseries{v3.\+2.\+6}}.

DOMPurify is written in Java\+Script and works in all modern browsers (Safari (10+), Opera (15+), Edge, Firefox and Chrome -\/ as well as almost anything else using Blink, Gecko or Web\+Kit). It doesn\textquotesingle{}t break on MSIE or other legacy browsers. It simply does nothing.

{\bfseries{Note that \href{https://github.com/cure53/DOMPurify/releases/tag/2.5.8}{\texttt{DOMPurify v2.\+5.\+8}} is the latest version supporting MSIE. For important security updates compatible with MSIE, please use the \href{https://github.com/cure53/DOMPurify/tree/2.x}{\texttt{2.\+x branch}}.}}

Our automated tests cover \href{https://github.com/cure53/DOMPurify/blob/main/test/karma.custom-launchers.config.js\#L5}{\texttt{28 different browsers}} right now, more to come. We also cover Node.\+js v18.\+x, v19.\+x, v20.\+x, v21.\+x, v22.\+x and v23.\+x, running DOMPurify on \href{https://github.com/jsdom/jsdom}{\texttt{jsdom}}. Older Node versions are known to work as well, but hey... no guarantees.

DOMPurify is written by security people who have vast background in web attacks and XSS. Fear not. For more details please also read about our \href{https://github.com/cure53/DOMPurify/wiki/Security-Goals-&-Threat-Model}{\texttt{Security Goals \& Threat Model}}. Please, read it. Like, really.\hypertarget{README.md_autotoc_md10725}{}\doxysubsection{\texorpdfstring{What does it do?}{What does it do?}}\label{README.md_autotoc_md10725}
DOMPurify sanitizes HTML and prevents XSS attacks. You can feed DOMPurify with string full of dirty HTML and it will return a string (unless configured otherwise) with clean HTML. DOMPurify will strip out everything that contains dangerous HTML and thereby prevent XSS attacks and other nastiness. It\textquotesingle{}s also damn bloody fast. We use the technologies the browser provides and turn them into an XSS filter. The faster your browser, the faster DOMPurify will be.\hypertarget{README.md_autotoc_md10726}{}\doxysubsection{\texorpdfstring{How do I use it?}{How do I use it?}}\label{README.md_autotoc_md10726}

DOMPurify technically also works server-\/side with Node.\+js. Our support strives to follow the \href{https://nodejs.org/en/about/releases/}{\texttt{Node.\+js release cycle}}.

Running DOMPurify on the server requires a DOM to be present, which is probably no surprise. Usually, \href{https://github.com/jsdom/jsdom}{\texttt{jsdom}} is the tool of choice and we {\bfseries{strongly recommend}} to use the latest version of {\itshape jsdom}.

Why? Because older versions of {\itshape jsdom} are known to be buggy in ways that result in XSS {\itshape even if} DOMPurify does everything 100\% correctly. There are {\bfseries{known attack vectors}} in, e.\+g. {\itshape jsdom v19.\+0.\+0} that are fixed in {\itshape jsdom v20.\+0.\+0} -\/ and we really recommend to keep {\itshape jsdom} up to date because of that.

Please also be aware that tools like \href{https://github.com/capricorn86/happy-dom}{\texttt{happy-\/dom}} exist but {\bfseries{are not considered safe}} at this point. Combining DOMPurify with {\itshape happy-\/dom} is currently not recommended and will likely lead to XSS.

In version 1.\+0.\+9, support for \href{https://github.com/w3c/webappsec-trusted-types}{\texttt{Trusted Types API}} was added to DOMPurify. In version 2.\+0.\+0, a config flag was added to control DOMPurify\textquotesingle{}s behavior regarding this.

\begin{DoxyItemize}
