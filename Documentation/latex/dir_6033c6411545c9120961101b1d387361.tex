\item {\bfseries{jspdf.\+node.\texorpdfstring{$\ast$}{*}.js}}\+: For running in Node. Uses file operations for loading/saving files instead of browser APIs.

\item {\bfseries{polyfills\texorpdfstring{$\ast$}{*}.js}}\+: Required polyfills for older browsers like Internet Explorer. The es variant simply imports all required polyfills from {\ttfamily core-\/js}, the umd variant is self-\/contained.
\end{DoxyItemize}

\hypertarget{README.md_autotoc_md11949}{}\doxysubsection{\texorpdfstring{Use of Unicode Characters / UTF-\/8\+:}{Use of Unicode Characters / UTF-\/8\+:}}\label{README.md_autotoc_md11949}
The 14 standard fonts in PDF are limited to the ASCII-\/codepage. If you want to use UTF-\/8 you have to integrate a custom font, which provides the needed glyphs. js\+PDF supports .ttf-\/files. So if you want to have for example Chinese text in your pdf, your font has to have the necessary Chinese glyphs. So, check if your font supports the wanted glyphs or else it will show garbled characters instead of the right text.

To add the font to js\+PDF use our fontconverter in \href{https://rawgit.com/MrRio/jsPDF/master/fontconverter/fontconverter.html}{\texttt{/fontconverter/fontconverter.html}}. The fontconverter will create a js-\/file with the content of the provided ttf-\/file as base64 encoded string and additional code for js\+PDF. You just have to add this generated js-\/\+File to your project. You are then ready to go to use set\+Font-\/method in your code and write your UTF-\/8 encoded text.

Alternatively you can just load the content of the \texorpdfstring{$\ast$}{*}.ttf file as a binary string using {\ttfamily fetch} or {\ttfamily XMLHttp\+Request} and add the font to the PDF file\+:


\begin{DoxyCode}{0}
\DoxyCodeLine{const\ doc\ =\ new\ jsPDF();}
\DoxyCodeLine{}
\DoxyCodeLine{const\ myFont\ =\ ...\ //\ load\ the\ *.ttf\ font\ file\ as\ binary\ string}
\DoxyCodeLine{}
\DoxyCodeLine{//\ add\ the\ font\ to\ jsPDF}
\DoxyCodeLine{doc.addFileToVFS("{}MyFont.ttf"{},\ myFont);}
\DoxyCodeLine{doc.addFont("{}MyFont.ttf"{},\ "{}MyFont"{},\ "{}normal"{});}
\DoxyCodeLine{doc.setFont("{}MyFont"{});}

\end{DoxyCode}
\hypertarget{README.md_autotoc_md11950}{}\doxysubsection{\texorpdfstring{Advanced Functionality}{Advanced Functionality}}\label{README.md_autotoc_md11950}
Since the merge with the \href{https://github.com/yWorks/jsPDF}{\texttt{y\+Works fork}} there are a lot of new features. However, some of them are API breaking, which is why there is an API-\/switch between two API modes\+:


\begin{DoxyItemize}
\item In "{}compat"{} API mode, js\+PDF has the same API as Mr\+Rio\textquotesingle{}s original version, which means full compatibility with plugins. However, some advanced features like transformation matrices and patterns won\textquotesingle{}t work. This is the default mode.
\item In "{}advanced"{} API mode, js\+PDF has the API you\textquotesingle{}re used from the y\+Works-\/fork version. This means the availability of all advanced features like patterns, Form\+Objects, and transformation matrices.
\end{DoxyItemize}

You can switch between the two modes by calling


\begin{DoxyCode}{0}
\DoxyCodeLine{doc.advancedAPI(doc\ =>\ \{}
\DoxyCodeLine{\ \ //\ your\ code}
\DoxyCodeLine{\});}
\DoxyCodeLine{//\ or}
\DoxyCodeLine{doc.compatAPI(doc\ =>\ \{}
\DoxyCodeLine{\ \ //\ your\ code}
\DoxyCodeLine{\});}

\end{DoxyCode}
