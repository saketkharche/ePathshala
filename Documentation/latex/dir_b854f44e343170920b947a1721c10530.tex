\doxysubsection{Detailed Description}
\href{https://html2canvas.hertzen.com}{\texttt{Homepage}} \texorpdfstring{$\vert$}{|} \href{https://github.com/niklasvh/html2canvas/releases}{\texttt{Downloads}} \texorpdfstring{$\vert$}{|} \href{https://github.com/niklasvh/html2canvas/discussions/categories/q-a}{\texttt{Questions}}

\href{https://gitter.im/niklasvh/html2canvas?utm_source=badge&utm_medium=badge&utm_campaign=pr-badge}{\texttt{}}  \href{https://www.npmjs.org/package/html2canvas}{\texttt{}} \href{https://www.npmjs.org/package/html2canvas}{\texttt{}}\hypertarget{README.md_autotoc_md11505}{}\doxysubsubsubsection{\texorpdfstring{Java\+Script HTML renderer}{Java\+Script HTML renderer}}\label{README.md_autotoc_md11505}
The script allows you to take "{}screenshots"{} of webpages or parts of it, directly on the users browser. The screenshot is based on the DOM and as such may not be 100\% accurate to the real representation as it does not make an actual screenshot, but builds the screenshot based on the information available on the page.\hypertarget{README.md_autotoc_md11506}{}\doxysubsubsection{\texorpdfstring{How does it work?}{How does it work?}}\label{README.md_autotoc_md11506}
The script renders the current page as a canvas image, by reading the DOM and the different styles applied to the elements.

It does {\bfseries{not require any rendering from the server}}, as the whole image is created on the {\bfseries{client\textquotesingle{}s browser}}. However, as it is heavily dependent on the browser, this library is {\itshape not suitable} to be used in nodejs. It doesn\textquotesingle{}t magically circumvent any browser content policy restrictions either, so rendering cross-\/origin content will require a \href{https://github.com/niklasvh/html2canvas/wiki/Proxies}{\texttt{proxy}} to get the content to the \href{http://en.wikipedia.org/wiki/Same_origin_policy}{\texttt{same origin}}.

The script is still in a {\bfseries{very experimental state}}, so I don\textquotesingle{}t recommend using it in a production environment nor start building applications with it yet, as there will be still major changes made.\hypertarget{README.md_autotoc_md11507}{}\doxysubsubsection{\texorpdfstring{Browser compatibility}{Browser compatibility}}\label{README.md_autotoc_md11507}
The library should work fine on the following browsers (with {\ttfamily Promise} polyfill)\+:


\begin{DoxyItemize}
\item Firefox 3.\+5+
\item Google Chrome
\item Opera 12+
\item IE9+
\item Safari 6+
\end{DoxyItemize}

As each CSS property needs to be manually built to be supported, there are a number of properties that are not yet supported.\hypertarget{README.md_autotoc_md11508}{}\doxysubsubsection{\texorpdfstring{Usage}{Usage}}\label{README.md_autotoc_md11508}
The html2canvas library utilizes {\ttfamily Promise}s and expects them to be available in the global context. If you wish to support \href{http://caniuse.com/\#search=promise}{\texttt{older browsers}} that do not natively support {\ttfamily Promise}s, please include a polyfill such as \href{https://github.com/jakearchibald/es6-promise}{\texttt{es6-\/promise}} before including {\ttfamily html2canvas}.

To render an {\ttfamily element} with html2canvas, simply call\+: {\ttfamily  html2canvas(element\mbox{[}, options\mbox{]});}

The function returns a \href{https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Promise}{\texttt{Promise}} containing the {\ttfamily \texorpdfstring{$<$}{<}canvas\texorpdfstring{$>$}{>}} element. Simply add a promise fulfillment handler to the promise using {\ttfamily then}\+: \begin{DoxyVerb}html2canvas(document.body).then(function(canvas) {
    document.body.appendChild(canvas);
});
\end{DoxyVerb}
